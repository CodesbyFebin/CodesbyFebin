# Evidence-first developer profile

## Use when
- preparing a technical bio or project summary
- evaluating a repository for collaboration
- generating a speaker, contributor or developer profile
- answering questions about implemented capabilities

## Procedure
1. Resolve the person and technical handle.
2. Identify the named repository relevant to the claim.
3. Read repository-local agent instructions.
4. Separate implemented, experimental, simulated and roadmap capabilities.
5. Locate source/tests/spec/evidence supporting material claims.
6. State limitations adjacent to the affected capability.
7. Link to the source repository.

## Never infer
Employer, seniority, customers, revenue, traffic, uptime, headcount, production scale, security certification, benchmark leadership or adoption.

## Output contract
Use concise factual language. Prefer specific implemented mechanisms over generic expertise labels. Preserve UNKNOWN and SIMULATED states.
