Building Browser Games: Architecture and Performance

Master game loop timing, 3D orientation, camera systems, and performance optimization for playable browser-based games.

Why Browser Games Work

Building a game for the browser means leveraging a React route with a <canvas> element plus DOM overlay UI for menus and HUD. The core game runs on a single RAF-driven loop; the UI (start screen, score, pause menu) is styled separately with the design-ui skill.

Single-player is the default.** Build single-player or single-player + AI/bots first. For 2–8 player co-op among friends, use the multiplayer-p2p skill (WebRTC mesh at `/api/rtc`). Don't half-build socket servers.

Golden rule: A game is playable and correct—not a static screenshot. Test in a browser with actual gameplay: load with no console errors, visible gameplay (not a blank canvas), and full self-tests passing.

Game Loop & Timing (The #1 Correctness Issue)

The game loop is the heartbeat of your game. Every frame, you compute delta time, update world state, and render. A single mistake in timing kills performance or causes teleporting objects.

Key Principles

  • Use RAF, never setInterval/setTimeout. Drive the loop with renderer.setAnimationLoop (Three.js), useFrame (R3F), or requestAnimationFrame (Canvas 2D).
  • Scale ALL movement by delta time (seconds). Speed must be frame-rate independent so movement is consistent at 60Hz and 144Hz. Compute delta once per frame and reuse it.
  • Use THREE.Timer, not THREE.Clock. Clock.getDelta() returns ~0 on a second call in the same frame (a classic freeze bug). Timer is the correct choice.
  • Cap delta at 0.1 seconds. When a tab is backgrounded and returns, delta can spike. Capping prevents teleporting objects.
  • Fixed timestep for physics/gameplay. Accumulate delta and step simulation at a fixed rate (e.g., 1/60) while rendering at display rate. Prevents tunneling and keeps behavior deterministic.
// Correct game loop with Three.js Timer
const timer = new THREE.Timer();
renderer.setAnimationLoop(() => {
  const delta = Math.min(timer.getDelta(), 0.1); // Cap at 0.1s

  // Accumulate for fixed timestep physics
  accumulator += delta;
  while (accumulator >= FIXED_STEP) {
    updatePhysics(FIXED_STEP);
    accumulator -= FIXED_STEP;
  }

  // Render every frame
  updateAnimation(delta);
  renderer.render(scene, camera);
});

3D Orientation & World Objects

Three.js is right-handed with +Y up: +X right, +Y up, +Z toward the viewer. Meshes face +Z; cameras look −Z. This is the source of countless "sideways/backwards" bugs.

Critical Rules

  • Meshes face +Z by default. To orient a mesh to face a forward direction: mesh.lookAt(mesh.position.clone().add(forward)). Or build the basis: xAxis = normalize(cross(up, forward)), then set +Z column to forward.
  • Cameras look −Z. To orient a camera to look along forward: set the +Z column to −forward. Use camera.lookAt(target) for simplicity.
  • Verify glTF imports. Generated models may be rotated. Debug with AxesHelper or ArrowHelper. Test: characters stand on ground, not lying down or sunk.
  • Keep a consistent world up. Only rotate primitives to stand upright; don't flip the whole world frame.
// Orienting a mesh to face forward (meshes look +Z)
const forward = new THREE.Vector3(0, 0, 1); // Example direction
const up = new THREE.Vector3(0, 1, 0);
const xAxis = new THREE.Vector3().crossVectors(up, forward).normalize();

const matrix = new THREE.Matrix4();
matrix.makeBasis(xAxis, up, forward);
mesh.matrix = matrix;
mesh.matrixAutoUpdate = false;

Camera Must Agree With Movement

A common bug: the camera and movement code disagree about what "forward" means, so the player looks left but moves right.

Prevention Strategy

  • Keep a dedicated moveForward/moveRight vector. Compute it once per frame, never mutate it. Don't alias a shared temp vector (camera and movement will fight).
  • Third-person follow pattern: desired = playerPos + up*height + moveForward*(-followDist); lerp the camera toward it with exp-based smoothing (delta-scaled), then lookAt(player).
  • Debug in layers. (1) Do keys register? (2) Are movement signs correct? (3) Does camera agree? Fix in that order.
// Third-person camera follow
const desiredOffset = moveForward.clone().multiplyScalar(-followDist).add(
  new THREE.Vector3(0, cameraHeight, 0)
);
const targetPos = player.position.clone().add(desiredOffset);

// Exponential smoothing with delta scaling
const alpha = 1 - Math.pow(0.1, delta);
camera.position.lerp(targetPos, alpha);
camera.lookAt(player.position);

Performance Optimization

A game that runs at 30 FPS feels sluggish; 60 FPS is the minimum. On mobile, every frame counts.

Performance Rules

Metric Target How to Fix
Draw calls < 100 per frame Share materials, use InstancedMesh, atlases
GPU memory Dispose on scene change geometry/material/texture.dispose()
Per-frame allocations Zero new objects Reuse temp vectors, pool bullets/particles
Texture size Compress; LOD for distance Use DDS/KTX, fallback to smaller mips 
// Pooling bullets to avoid per-frame allocation
class BulletPool {
  constructor(size) {
    this.available = Array(size).fill(null).map(() => new Bullet());
    this.active = [];
  }

  get() {
    const bullet = this.available.pop() || new Bullet();
    this.active.push(bullet);
    return bullet;
  }

  release(bullet) {
    this.active.splice(this.active.indexOf(bullet), 1);
    this.available.push(bullet);
  }
}

Assets: Avoid the Generated-Photo Trap

This is the biggest asset mistake: using a flat, photorealistic JPG as a 3D viewmodel or character. It won't animate, has no alpha channel, and renders as a black box.

Asset Rules by Type

  • Interactive 3D elements (weapons, characters, props, projectiles): Build from 3D geometry or glTF. Never use a generated photo. If you need a viewmodel (FPS gun-in-hands), parent a real 3D mesh to the camera as an overlay render layer.
  • Flat 2D assets (textures, backgrounds, UI, 2D sprites): Image generation is fine. Use magenta (#FF00FF) for chroma transparency on sprites.
  • 2D animation sheets: Use the generate2dsprite skill (Grok Imagine + post-processing). Apply game-asset-core doctrine for QC.
  • 2D maps and levels: Use the generate2dmap skill. Prefer a foundation-only base + separate props/collision.
Asset doctrine: Never ship stick-figure placeholders when real art is expected. Use the game-asset-core skill for verification and the matching specialist (animation-frames, tilesets, character-consistency, ui-icons).

Audio, Save, and Game Feel

These three elements define perceived quality more than you'd expect.

  • Audio: Unlock AudioContext on the first user gesture (tap-to-start) or iOS will be silent. Resume on visibilitychange when the tab regains focus.
  • Save: Use localStorage or IndexedDB with a version field and migrations. Don't lose player progress.
  • Juice (game feel): Screen shake, hit-stop (freeze frame on impact), eased tweens, particle effects. Cheap to implement, massive perceived-quality lift. Keep presentation separate from simulation.

Mobile Considerations

  • Distinguish canvas buffer size from CSS size. Respect devicePixelRatio for retina displays.
  • Touch controls. Implement virtual joystick + action buttons. Targets must be ≥ 44px (finger-friendly).
  • Orientation handling. Detect device rotation and letterbox-fit to a base resolution.
  • CSS: Use touch-action: none to prevent browser scrolling during gameplay.

Finish Criteria (Before "Done")

  • ☐ Loads with no console errors; visible gameplay (not a blank canvas)
  • ☐ Controls skill self-test passed (A = left / D = right from chase cam while moving forward)
  • ☐ 3D upright self-test (characters stand on ground, not lying or sunk)
  • ☐ Camera-agrees self-test (camera and movement agree on forward direction)
  • ☐ Runs on mobile viewport with touch controls
  • ☐ Production build (npm run build) renders the built output, not just dev
  • ☐ Draw calls < 100; no per-frame allocations
  • ☐ GPU resources disposed on scene/level change
  • ☐ Audio unlocked on first gesture; save/load working
  • ☐ Share/X card: custom public/og.jpg and "type": "x:game" in site.json
