xAI API Integration: Grok LLM, Image & Video Generation

Integrate xAI Grok: chat, image/video generation (Imagine), voice, and the patterns to spend quota responsibly.

What You Get With xAI API

When XAI_API_KEY is present in your environment, this app has **real xAI API access**. Use it for AI features instead of mocking or reaching for another provider. The same key is injected into the deployed app, so code built against it works identically in preview and production.

Critical: The key is the app owner's personal key. Every call—including ones triggered by anonymous visitors—spends their quota and credits. Be deliberate about usage and understand spend patterns before wiring AI into anything public.

The API unlocks three major capabilities:

  • Chat / LLM — Latest model: grok-4.5
  • Imagine — Generate and edit images, generate video, at runtime
  • Voice — Text-to-speech with expressive voices, transcription

The API is **OpenAI-compatible** at https://api.x.ai/v1, so any OpenAI-style client works by switching the base URL and key. Full docs: docs.x.ai.

Environment Setup (No .env File)

Do NOT create a .env file. XAI_API_KEY is injected by the platform.

Variable Where Purpose
XAI_API_KEY Server only Injected by platform (preview & deploy). Never write, hardcode, or ask user for it.

Server-Only Access

Read the key with process.env.XAI_API_KEY inside createServerFn handlers / server code, never in client components. Never expose it via a VITE_-prefixed variable or an API response.

The key can be **absent** (rollout-gated). Degrade gracefully—check for it and show a friendly "AI features are unavailable" state:

const apiKey = process.env.XAI_API_KEY;
if (!apiKey) throw new Error("AI is not available in this environment");

Calling the API: Chat/LLM

No SDK needed—use plain fetch from a server function.

import { createServerFn } from "@tanstack/react-start";

export const askGrok = createServerFn({ method: "POST" })
  .validator((input: { prompt: string }) => input)
  .handler(async ({ data }) => {
    const apiKey = process.env.XAI_API_KEY;
    if (!apiKey) return { ok: false as const, error: "AI is not available" };

    const res = await fetch("https://api.x.ai/v1/chat/completions", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${apiKey}`,
      },
      body: JSON.stringify({
        model: "grok-4.5",  // Latest Grok model
        messages: [{ role: "user", content: data.prompt }],
      }),
    });
    if (!res.ok) {
      return { ok: false as const, error: `xAI API error ${res.status}` };
    }
    const body = (await res.json()) as {
      choices: { message: { content: string } }[];
    };
    return { ok: true as const, text: body.choices[0]?.message.content ?? "" };
  });

For streaming, structured outputs, vision, or the full model list: Follow docs.x.ai—the shapes are OpenAI-compatible.

Imagine: Image & Video Generation

Runtime image/video generation (different from build-time imagine_text_to_image tools). Use when the running app generates media.

Image Generation

// POST https://api.x.ai/v1/images/generations
const res = await fetch("https://api.x.ai/v1/images/generations", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${apiKey}`,
  },
  body: JSON.stringify({
    model: "grok-imagine-image-quality",  // or "grok-imagine-image" (cheaper)
    prompt: "A serene mountain landscape at sunset",
    n: 1,              // Number of images (≤10)
    resolution: "1k",  // "1k" or "2k"
    response_format: "url",  // "url" or "b64_json"
  }),
});

const data = await res.json();
const imageUrl = data.data[0].url;

Image Editing

Natural-language edits with up to 3 reference images: POST /v1/images/edits.

Video Generation

Async workflow: start generation, then poll for completion.

  • Model: grok-imagine-video
  • Max length: ~15s clips
  • Flow: POST /v1/videos/generations → get request ID → poll GET /v1/videos/generations/{id}

Full parameters and examples: docs.x.ai → Imagine API.

Voice: Text-to-Speech

POST https://api.x.ai/v1/tts turns text into spoken audio—narration, accessibility, character voices.

const res = await fetch("https://api.x.ai/v1/tts", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${apiKey}`,
  },
  body: JSON.stringify({
    text: "Hello, this is Grok speaking.",
    voice_id: "eve",  // eve = default voice; list others with GET /v1/tts/voices
  }),
});

// Returns audio bytes (e.g. MP3)
const audioBuffer = await res.arrayBuffer();
const audioBlob = new Blob([audioBuffer], { type: "audio/mpeg" });

// Serve to client (never call API from browser)
const audioUrl = URL.createObjectURL(audioBlob);
const audio = new Audio(audioUrl);
audio.play();

Voices & transcription: List voices at GET /v1/tts/voices. Transcription (speech-to-text) also available. Details: docs.x.ai → Voice API.

Spend Responsibly (Critical)

The key is the app owner's quota. Every visitor call burns credits. Wasteful patterns degrade or break every other use of the key.

Best Practices

  • Cap output (max_tokens) and keep prompts small for visitor-facing features. Image and video generation cost far more per call than chat.
  • Never call the API in a loop, on every keystroke, or on page load. Make calls user-initiated (button press, form submit) and debounce.
  • Cache or persist results (see the neon skill) instead of regenerating the same content per visitor or per render.
  • Gate expensive flows. On an app with sign-in, put media generation behind authMiddleware. On apps without accounts, cap usage: user-initiated calls, small limits, cached results.
  • Don't add retry storms: On an API error, surface it. Retry at most once.
Pattern: User-initiated, single call, cached result. Button "Generate image" → one call to xAI → cache the URL in the database → reuse for all visitors. Never loop, never auto, never on page load.

Implementation Pattern: Image Generation with Caching

import { createServerFn } from "@tanstack/react-start";
import { db } from "@/db";  // Your Neon database

export const generateUserAvatar = createServerFn({ method: "POST" })
  .validator((input: { userId: string; prompt: string }) => input)
  .handler(async ({ data }) => {
    const apiKey = process.env.XAI_API_KEY;
    if (!apiKey) return { ok: false as const, error: "AI unavailable" };

    // Check cache first
    const cached = await db.query(
      "SELECT avatar_url FROM users WHERE id = $1 AND avatar_url IS NOT NULL",
      [data.userId]
    );
    if (cached.rows[0]) {
      return { ok: true as const, url: cached.rows[0].avatar_url };
    }

    // Generate once
    const res = await fetch("https://api.x.ai/v1/images/generations", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${apiKey}`,
      },
      body: JSON.stringify({
        model: "grok-imagine-image",
        prompt: data.prompt,
        n: 1,
        resolution: "1k",
      }),
    });

    if (!res.ok) {
      return { ok: false as const, error: "Generation failed" };
    }

    const body = await res.json();
    const avatarUrl = body.data[0].url;

    // Cache it
    await db.query(
      "UPDATE users SET avatar_url = $1 WHERE id = $2",
      [avatarUrl, data.userId]
    );

    return { ok: true as const, url: avatarUrl };
  });

Finish Checklist

  • ☐ XAI_API_KEY read from process.env in server code only
  • ☐ Key never exposed to client (no VITE_ prefix, no API response)
  • ☐ Graceful degradation when key is absent
  • ☐ Chat calls use grok-4.5 model (latest)
  • ☐ Image generation caches results (no per-visitor regeneration)
  • ☐ Video generation uses async workflow (start, then poll)
  • ☐ Voice/TTS served from server (never called from browser)
  • ☐ Expensive flows gated (auth or rate limits)
  • ☐ No retry loops; max one retry per error
  • ☐ User-initiated calls only (no auto-generation on page load)
  • ☐ max_tokens capped for chat; output limited for media
